Problem

  • Token explosion — agents pipe massive DOMs to LLMs at every step, burning 100k+ tokens
  • 80% failure rate — SAP, public portals, complex SaaS break DOM-only agents
  • Active-X & legacy forms — Chrome MCP or Claude Computer Use alone cannot clear them
  • Site owner AI risk — agents click wrong buttons, causing order errors and complaints
  • Vendor lock-in fear — Anthropic-only or OpenAI-only standards exclude rival agents

Solution

  • Ship ai-friction-manifest.json — the site declares its own agent playbook
  • SHA-256 verification — central registry rejects tampered manifests (Claim 2)
  • Three delivery methods — /.well-known, <meta>, HTTP header (Claim 3)
  • Active-X handling — manual_signature and action_fallback first-class
  • MIT + FRAND + IETF — vendor-neutral, on the standards track

How It Works — 3 Steps

1

Publish

Site owner (or SI partner) ships /.well-known/ai-friction-manifest.json. Optional X-AI-Manifest HTTP header alongside.

2

Verify

Agent fetches the manifest once. SHA-256 hash is queried against the central registry which returns white / gray / black.

3

Execute

Agent runs steps deterministically — no DOM re-inference. 95~98% token savings, 100% task success.
